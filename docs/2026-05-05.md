# 2026-05-05 작업 정리

04-30 이월 항목 중 **#1 점수 가중치 재조정**을 처리했다.
어제의 백테스트에서 "점수 ↑ ≠ 수익률 ↑"이 데이터로 확인됐고,
오늘은 그것을 회귀로 정량화해 신규 가중치 후보를 뽑아냈다.

## 1. 가중치 튜닝 스크립트 — [scripts/tune_weights.py](scripts/tune_weights.py)

### 동작
1. 유니버스 모든 종목 × 모든 거래일에 대해 4개 sub-component 점수와 익일 시초가 수익률 수집
   (top_n / threshold 필터 없음 → 회귀용 풀 샘플)
2. OLS 회귀 (numpy `lstsq`, 절편 포함): `ret% ~ a*volume + b*resistance + c*candle + d*consolidation`
3. 음수 계수 → 0 클리핑 후 합=1 정규화 → 신규 가중치 제안
4. 기존/신규 가중치로 simulate를 각각 돌려 픽 수·승률·평균수익 비교

`backtest_closing_bet.py`의 `simulate()`는 `composite()` 하드코딩 의존이라 가중치 교체가 안 된다.
그래서 `evaluate_weights()`를 별도로 두고 `composite_with_weights(comps, weights)`로 동적 합산했다.

### 왜 별도 스크립트인가
백테스트 스크립트는 "현재 점수 → 임계값 분포"를 본다. 튜닝은 그 점수가 **얼마나 옳은지**를 본다.
역할이 다르고, 튜닝은 회귀를 위해 top_n 필터 없이 전 종목 데이터를 모아야 한다.
backtest를 확장하기보다 분리하는 쪽이 깔끔.

## 3. 해석과 한계

### 핵심 발견
**"종베에서 수익을 만드는 건 거래대금 surge 단 하나"** — 적어도 26종목·1년 4개월 표본에선 그렇다.
저항선 이격·캔들 모양·조정 후 회복은 **음의 상관** — 점수가 높을수록 익일 시초가가 오히려 낮다.

이건 직관에 반하지만, 가능한 설명:
- 저항 근처 종목 = 매물대 부담으로 시초가 매도 압력
- 캔들이 깨끗하면(위꼬리 짧음) 이미 종가에 매수세가 들어왔다는 뜻 → 익일 추가 매수 부족
- 조정 후 회복 점수가 높다 = 이미 회복 구간 = 모멘텀 둔화

즉 **"매수 사인을 늦게 잡고 있다"** 는 가설이 맞을 가능성.

### 한계
- R²=0.0096은 노이즈 수준. 회귀계수의 부호는 신뢰할 수 있지만 *크기*는 표본의존성이 크다
- 신규 가중치 (1.0/0/0/0) 적용은 너무 극단적 — `composite() = volume_surge` 가 되면 **오직 거래대금만 보는 매수**가 된다
- 표본이 26종목 / 1.3년이라 강세장 편향. 약세장 데이터가 들어가면 부호가 바뀔 수 있음
- institutional은 백테스트에서 None=0 고정이라 회귀 대상에서 빠짐 → 운영 시 가중을 별도 결정해야

### 즉시 적용은 보류
회귀 결과를 그대로 `scorer.py`에 박지는 않았다. 이유:
1. 단일 컴포넌트 가중은 점수 다양성이 사라짐 (다른 모든 종목이 0점이 됨)
2. 음신호 컴포넌트 3개를 0으로 죽이는 대신, **합산식 자체를 재설계**해야 함
   - 예: `volume_surge - α*resistance_proximity` 같은 차감식
   - 또는 sub-component 자체의 점수화 함수를 뒤집기 (저항 근처일수록 *낮은* 점수)
3. 더 큰 유니버스(키움 시총 100)에서 한 번 더 검증 필요

오늘 산출물은 **다음 액션의 근거 자료**이지 자동 적용이 아니다.

## 9. Score 함수 v2 재설계 — [src/mcp_servers/closing_bet_mcp/scorer.py](src/mcp_servers/closing_bet_mcp/scorer.py)

### 가설
회귀에서 일관되게 음신호로 나온 두 함수를 재설계:

1. **resistance_proximity_v2** — "거의 고점(-8~-3%)"이 매물대 부담이라는 가설.
   분포를 뒤집어 **breakout(gap > 0)** 과 **깊은 눌림(-25 ~ -10%)** 을 보상.
2. **candle_shape_v2** — 위꼬리 = 장중 매도 분출 → 익일 시초가 추격매수 여지.
   v1의 "짧은 위꼬리 + 양봉" 보상을 뒤집어 **위꼬리 비율에 비례** 보상.

`compute_technical_scores_v2`로 묶고, v1은 그대로 둠 (live MCP 도구 영향 없음).
[scripts/tune_weights.py](scripts/tune_weights.py)에 `--scorer {v1,v2}` 플래그 추가.

### 결과 — [docs/tune_weights_rolling_v2.md](docs/tune_weights_rolling_v2.md)

동일 조건(마스터 500 / 매일 200 / 2025-01-01 ~ 2026-04-30, 46,001 샘플) 회귀:

| sub-component | v1 계수 | **v2 계수** | 가설 검증 |
|---------------|---------|-------------|-----------|
| volume_surge | +0.00463 | +0.00344 | 그대로 양신호 |
| resistance_proximity | -0.00453 | **-0.00008** | △ 음신호 중화됐으나 양신호로는 못 감 |
| candle_shape | -0.00226 | **+0.00178** | ✅ **부호 반전 성공** |
| consolidation | +0.00049 | -0.00054 | 노이즈 범위 |

R²: v1 0.0034 → v2 0.0011 (오히려 *낮아짐*).

### 백테스트 비교

| 조합 | 픽 수 | 승률 | 평균수익 |
|------|-------|------|----------|
| v1 + 기존 weights (0.25/0.20/0.15/0.20) | 1,153 | 51.0% | +0.80% |
| v1 + 신규 weights (0.90/0/0/0.10) | 1,143 | 52.8% | **+0.86%** |
| v2 + 기존 weights | 1,064 | **54.6%** | +0.71% |
| v2 + 신규 weights (0.66/0/0.34/0) | 1,157 | 52.2% | +0.32% |

가장 좋은 평균수익은 **v1 + 신규 weights** (+0.86%).
가장 좋은 승률은 **v2 + 기존 weights** (54.6%).
**v2 + 신규 weights는 최악** — 점수 재설계와 가중치 회귀를 동시에 적용하면 오히려 손해.

### 해석

- **candle 재설계는 옳았다**: 회귀에서 부호가 깔끔히 뒤집힘. 위꼬리 = 익일 갭상승 신호 가설 확인.
- **resistance 재설계는 미완**: breakout 보상이 안 먹힘. 음신호는 사라졌지만 양신호로 가지는 못함.
  → 60일 고점 자체가 종베 시그널로 약한 게 본질일 가능성. 60일이 아니라 *5–10일* 단기 고점이거나,
  돌파 거래량 같은 *상호작용 변수* 가 필요할 수도.
- **v2 신규 weights가 오히려 나빠짐**: candle 가중이 0.34로 들어가면서 의미 있는 신호(volume)의 비중이
  희석됨. 회귀의 가중치 추정은 R²가 너무 낮아 과적합 위험이 큼.

### 잠정 합의안 (운영 적용은 보류)

회귀 결과를 그대로 따르기보다 **하이브리드**:
- volume_surge: v1, 가중 0.7
- candle_shape: **v2** (위꼬리 보상), 가중 0.2
- consolidation: v1, 가중 0.1
- resistance_proximity: 양/음 어느 쪽도 안정적 양신호 못 만듦 → **가중 0으로 제외**
- institutional: 운영 시 별도 가산 (백테스트 데이터 부재)

이걸 곧장 `composite()`에 박지는 않았다. 다음 단계 검증 후 적용.

## 12. Catalyst (재료) 신호 통합 — DART 공시 기반

### 동기
종베 매매 핵심 요약과 우리 전략 비교 결과, **재료(catalyst) 신호 부재가 가장 큰 구조적 결함**으로 드러남.
naver_news_mcp는 historical 검색이 안 돼 백테스트 불가 → DART 공시(`OpenDartReader`)로 우회.
공시는 `rcept_dt` 가 명시돼 있어 회귀 표본에 그대로 투입 가능.

### 변경

**[scripts/_dart_cache.py](scripts/_dart_cache.py)** 신규
- `load_disclosures(code, start, end)` — 종목별 공시 리스트 디스크 캐시 (`docs_cache/dart/`)
- 1회 fetch → JSON 저장 → 재실행 시 즉시 로딩

**[src/mcp_servers/closing_bet_mcp/scorer.py](src/mcp_servers/closing_bet_mcp/scorer.py)**
- `TechnicalScores`에 `catalyst: float = 0.0` 필드 추가
- `score_catalyst(disclosures, target_date, lookback_days=3)` 신규
  - 호재 키워드 16종(`단일판매ㆍ공급계약`, `신규시설투자`, `자기주식취득`, `임상결과`, `흑자전환` …) → +35점
  - 악재 키워드 11종(`유상증자`, `감자`, `영업정지`, `소송` …) → -25점
  - recency 가중: T-0=1.0, T-1=0.7, T-2=0.4, T-3=0.1
  - 합산 후 0~100 클리핑
- `compute_technical_scores` / `_v2` 에 `disclosures` / `target_date` 인자 추가 (미제공시 catalyst=0)

**[scripts/tune_weights.py](scripts/tune_weights.py)**
- `--catalyst` 플래그 추가: 켜면 종목별 공시 fetch + 회귀 X 매트릭스 5번째 컬럼으로 catalyst 추가
- `fit_ols`의 절편 인덱싱 4 → -1 일반화 (회귀 변수 개수 가변)

### Sanity 결과 — [docs/tune_weights_catalyst_sanity.md](docs/tune_weights_catalyst_sanity.md)

마스터 100 / 매일 50 / 2025-06-01 ~ 2026-04-30 / 16,630건 공시 fetch / 6,700 회귀 샘플:

| sub-component | 회귀계수 | 부호 |
|---------------|----------|------|
| volume_surge | +0.01210 | + |
| resistance_proximity | -0.00737 | - |
| candle_shape | -0.00255 | - |
| consolidation | -0.00638 | - |
| **catalyst** | **-0.00454** | **-** |

R² = 0.0131 (catalyst 없을 때 0.0129) — **개선 거의 없음**.

### 예상 못 한 결과: catalyst가 음신호

종베 본질에 따르면 재료가 #1 시그널이어야 하는데, 회귀에서 음의 계수가 나옴.
가능한 설명:

1. **표본 편향 (large-cap)** — 시총 상위 100은 공시가 일상적(배당·IR·임원거래). "단일판매·공급계약"이
   매칭되어도 매출 대비 비중이 작아 가격 영향 미미. 종베가 통하는 *중·소형 모멘텀*은 표본에 거의 없음.
2. **정보 효율** — 공시 시점에 이미 가격이 반영됨. T+1 시초가는 오히려 정상화(되돌림) 구간 가능성.
3. **lookback 3일이 너무 김** — 가까운 시점일수록 노이즈 수렴. 장 마감 직전 단독기사 같은
   "오늘 발생한 임팩트" 와 DART 공시(보통 장후 게재)는 시간축이 다름.
4. **키워드 매칭의 거칠음** — 단순 부분일치라 "단일판매·공급계약체결*철회*" 같은 부정형도 +로 잡힘.
   공시 종목분류(`pblntf_ty`)와 본문 fetch 없이는 정밀도 한계.

### 즉시 결론

**현재 정의의 catalyst 점수는 작동하지 않는다** — 곧장 composite()에 박지 말 것.
3가지 후속 시도가 필요:

1. **유니버스 확장** — 시총 상위 500보다 더 넓게(시총·거래량 둔감), 중·소형주에서 catalyst가 살아나는지
2. **lookback=1로 단축** + 당일(T-0) 공시만 가산 — 공시일 *근처* 가 아니라 *직후* 효과 측정
3. **키워드 정교화** — DART 보고서 분류코드(`pblntf_ty`)로 "주요사항보고", "거래소 공시 의무" 등
   카테고리 단위 필터링. 단순 제목 부분일치 탈피

이 셋을 다 해본 뒤에도 음신호가 유지된다면, **종베의 재료는 DART 공시가 아니라 뉴스/리포트**라는
의미 — 그 경우 historical news 데이터셋(예: 한국언론진흥재단 빅카인즈) 확보 단계로 넘어감.

### 인프라 측면 수확

- DART 공시 캐시 인프라 완성 ([scripts/_dart_cache.py](scripts/_dart_cache.py)) — 다음 시도들에서
  재사용. 100종목·1년치가 16K건이고 디스크 < 5MB.
- scorer가 이제 6번째 차원(catalyst)을 가진다. 백테스트·라이브 둘 다 동일 인터페이스로 호출 가능.
- `--catalyst` 플래그로 ON/OFF 토글 — A/B 실험에 즉시 활용.
