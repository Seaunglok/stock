## 4. 해석

### 왜 하이브리드가 더 나빠졌나
회귀 계수만 보면 candle v2 = +0.00178 vs volume = +0.00463. **양신호이긴 하나 volume의 38% 수준**.
volume 가중을 0.90 → 0.70 으로 22pp 양보하고 candle v2에 0.20을 주면, 점수 분포에서 *진짜* 강한 신호(volume)의 비중이 희석된다.

점수구간별로 봐도 명확:
- v1+new 80–100구간: 930픽 / +0.92%  ← 강한 volume 신호가 명확히 분리됨
- hybrid 80–100구간: 907픽 / +0.60%  ← 같은 구간인데 평균수익 32bp 낮음

picks 수는 거의 같은데 평균이 낮다는 건, **candle v2 가산이 "좋은 픽이 아닌 것"의 점수까지 끌어올려 픽 풀의 질을 낮췄다**는 뜻.

### 일반화
회귀 R² = 0.0034 (rolling), 0.0011 (v2 적용). **계수 부호는 신뢰할 수 있어도, 다중 신호를 가중 평균해 합치는 방식 자체의 마진이 거의 없다.** volume 단변량(+가벼운 consolidation 보강)으로 "강한 신호만 보고 베팅"하는 게 단순 합산식의 한계 안에서 최적.

### 도메인 가설이 틀린 게 아니라, *합산식 형태가 부적합*
candle v2 부호 반전은 회귀상 사실이다. 다만:
- 모든 컴포넌트를 가중평균으로 합치면 → 신호 강도 차이가 가중치에 묻힘
- 진짜 필요한 건 **gating** 또는 **interaction**:
  - 예: `if volume_surge >= 80 then composite *= (1 + 0.2 * candle_v2/100)` (volume 통과 후 보너스)
  - 또는 단일 점수가 아닌 **multi-criteria 룰** (volume ≥ 80 AND candle_v2 ≥ 60 형태)

선형 가중평균에 더 깎고 더하고 해서 짜낼 수 있는 마진은 v1+new 가 사실상 천장이라는 게 오늘의 결론.

## 5. 즉시 결정

- **운영 적용은 v1 + new (0.90/0/0/0.10) 로 결론.** 하이브리드는 보류.

## 6. 다음 단계 (우선순위 재정렬)

선형 합산 튜닝의 한계가 보였으니 방향을 바꾼다:

1. **룰 기반 필터링** — 점수 가중평균 대신 "volume ≥ 80 AND consolidation ≥ 50" 같은 합집합 조건으로 픽 산출. 합산식 우회.
2. **gating composite** — volume 통과 시에만 candle/consolidation 가산점, 통과 못하면 0. 비선형.
3. **interaction feature 회귀 재시도** — `volume × candle_v2` 같은 교차항을 변수로 추가해 R² 개선 여지 확인.
4. **catalyst 재시도** — 05-05 §12 후속 (lookback=1, T-0만, 중·소형주 유니버스)

다음 작업은 #1(룰 기반)을 빠르게 백테스트해서 선형 합산 천장을 깰 수 있는지 확인하는 게 맞다고 본다.

### 10.3 해석

1. **완화 weak 효과 단독 검증 실패** — KOSPI 신호 부재로 1차/2차 비교가

2. **inverted cut 75 도 마진 미미** — +0.3pp / +3bp. score≥75 컷이 충분히 강하지
   않거나, 합산 분포 상위가 이미 픽 풀의 대부분이라 추가 컷의 의미가 작음.
3. **레짐별 분해 패턴은 1차와 일관** — strong 레짐 픽이 가장 약하고 weak/neutral
   가 더 좋음. 즉 "약세장 종베가 잘 먹힌다" 는 1차의 핵심 결론은 프록시 기반에서도

   2차는 KOSPI 데이터 복구되면 재실행 필요.

### 10.5 후속 후보

1. KOSPI 페치 복구 (FDR 우회 경로 또는 다른 인덱스 종목 005930+000660 가중평균
   프록시 등) 후 2차 재실행.
2. weak 정의 sensitivity sweep — KOSPI cut ∈ {-1.5, -1.0, -0.7, -0.5}, adv cut ∈
   {0.30, 0.35, 0.40, 0.45} 그리드.
3. 약세 + score 컷 결합 — `regime==weak AND composite ≥ 60` (현 weak-only 는
   composite 컷 없음).
4. PLAYBOOK A 프롬프트 룰 갱신 (검증 끝난 후).
