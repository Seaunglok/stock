## 1. `scripts/direct_closing_bet.py` 생성

### 배경

기존 `scripts/auto_closing_bet.py`는 Anthropic Claude API를 통해 AnalysisAgent → SupervisorAgent 전체 스택을 거쳤다.
크레딧 소진(400 에러)으로 파이프라인 전체가 멈추는 문제가 있었다.

### 해결 방식

| 항목 | 기존 (`auto_closing_bet.py`) | 새 버전 (`direct_closing_bet.py`) |
|------|------------------------------|-----------------------------------|
| 데이터 수집 | DataCollector A2A → kiwoom-market-mcp | **pykrx** 직접 호출 (API 불필요) |
| 채점 | AnalysisAgent A2A → closing-bet-mcp | **Python 함수 직접 import** |
| 주문 실행 | TradingAgent A2A → trading-domain | MCPManager → trading-domain :8030 **유지** |
| Claude API 필요 여부 | 필수 | **불필요** |

### 사용 방법

```bash
python scripts/direct_closing_bet.py --test              # 즉시 선별 테스트 (주문 없음)
python scripts/direct_closing_bet.py --daemon            # 스케줄러 데몬 (14:50/15:20/09:00)
python scripts/direct_closing_bet.py --status            # 현재 상태 확인
python scripts/direct_closing_bet.py --phase selection   # 단계 수동 실행
python scripts/direct_closing_bet.py --phase buy
python scripts/direct_closing_bet.py --phase sell
```

### 스케줄

| 시각 | 동작 |
|------|------|
| 14:50 | 후보 선별 (pykrx + scoring) |
| 15:20 | 종가 시장가 매수 (trading-domain MCP) |
| 09:00 (다음날) | 시초가 기준 청산 판단 → 매도 |

### 포지션 사이징 (PLAYBOOK C)

| composite 점수 | 투자금 배수 |
|----------------|------------|
| 85점 이상 | `INVESTMENT_PER_TRADE × 2.0` |
| 70~85점 | `INVESTMENT_PER_TRADE × 1.5` |
| 50~70점 | `INVESTMENT_PER_TRADE × 1.0` |

`INVESTMENT_PER_TRADE` 기본값: 500,000원 (`.env`에서 조정 가능)

## 2. Telegram 알림 연동

### 설정 항목 (`.env`)

```env
TELEGRAM_BOT_TOKEN=<BotFather에서 발급>
TELEGRAM_CHAT_ID=<numeric chat_id>
```

### chat_id 발급 과정

1. Telegram `@BotFather` → `/newbot` → 토큰 발급
2. 봇에게 `/start` 메시지 전송
3. `getUpdates` API로 chat_id 확인:
   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```
4. 반환된 `message.chat.id` (숫자 형식) 를 `TELEGRAM_CHAT_ID`에 입력

> 주의: 봇 username(`@stock_hama_bot`)이 아닌 숫자 ID여야 한다.

### 알림 발송 시점

- 후보 선별 완료 (종목명, 점수, 예상 수량)
- 시장 필터 NG 시 (KOSPI 기준 미충족)
- 매수 완료
- 청산 결과 (P&L 포함)
- 오류 발생

## 4. 스코어러 분석 기준 개선

### 분석 결과

`direct_closing_bet.py`가 `compute_technical_scores`(v1)를 사용 중이었으나, `scorer.py`에 회귀 분석 결과가 이미 기록되어 있었다:
- v1 캔들(candle_shape): **음신호** — 위꼬리 짧은 양봉을 좋게 봤으나 실제로는 역효과
- v2 캔들: **양신호** — 위꼬리가 큰 종목이 익일 추격 매수 유입 가설과 일치
- v2 resistance: 음신호 중화 수준 → v1 유지가 유리

### 수정 사항

| 항목 | 이전 | 이후 |
|------|------|------|
| 스코어러 | `compute_technical_scores` (v1) | `compute_technical_scores_hybrid` |
| 캔들 분석 | v1 (위꼬리 짧은 양봉 우대) | **v2 (위꼬리 큰 종목 우대)** |
| 전고점 이격 | v1 60일 기준 | v1 **90일** 기준으로 확장 |
| 기간 조정 | 60일 창 | **90일 창 + 30봉 이상 조정 시 +10점** |
| OHLCV 조회 기간 | 90일 | **120일** (scorer 90봉 활용 보장) |

### 전고점 이격 기준 (`score_resistance_proximity` v1)

만점 구간: 90일 전고점 대비 **-8% ~ -3%** 이격

```
gap_pct = (현재가 - 90일고점) / 90일고점 × 100

-8% ~ -3%  → 100점  (전고점 바로 아래 = 매물대 직전)
-3% ~ 0%   →  70점
 0% ~ +3%  →  40점  (돌파 직후 = 부담)
-15% ~ -8% →  60점
그 외       →  점차 감소
```

### 기간 조정 기준 (`score_consolidation`)

90일 고점 이후 조정(-8%~-25%) → 회복 패턴 감지.  
조정 기간 30봉(약 6주) 이상이면 **+10점** 보너스 추가.

### 7.1 KS11 복구 (`backtest_with_breadth_gate.py`)

**원인**: `pykrx`의 `stock.get_index_ohlcv()` → pykrx ≥1.0에서 제거됨.  
**수정**: `stock.get_index_ohlcv_by_date()` 로 교체. 성공 시 로그 출력 추가.

```python
# 수정 전 (깨진 API)
pdf = stock.get_index_ohlcv(s_compact, e_compact, "1001")
# 수정 후
pdf = stock.get_index_ohlcv_by_date(s_compact, e_compact, "1001")
```

폴백 체인: FDR → **pykrx(수정됨)** → 005930+000660 프록시 → 비활성.

### 7.2 sector_vol neutral-only 모드 (`backtest_regime_adaptive.py`)

**실험 근거**: D+E-vol에서 strong 레짐 52.4%가 neutral(56.0%)·weak(53.5%)보다 약함.  
가설: strong 레짐에서는 섹터 집중이 오히려 방해 → strong은 종가매매로 폴백하면?

새 시나리오 **D+E-vol-N** 추가:

| 레짐 | D+E-vol (기존) | D+E-vol-N (신규) |
|------|---------------|-----------------|
| weak | 종가매매 | 종가매매 |
| neutral | 섹터RS+거래량 | 섹터RS+거래량 |
| **strong** | 섹터RS+거래량 | **종가매매 폴백** |

```bash
# 실행 방법 (기존과 동일, sector_vol_N 자동 포함)
python scripts/backtest_regime_adaptive.py --html docs/backtest_regime_adaptive.html
```
