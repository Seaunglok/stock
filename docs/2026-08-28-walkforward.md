# 워크포워드 검증 하니스 + 첫 결과 (2026-08-28)

## 왜 만들었나

이 프로젝트의 A/B 는 전부 **같은 데이터를 반복해서 보고** 그중 좋아 보이는 값을 채택해 왔다.
그렇게 채택한 값이 구간을 바꾸자 뒤집혔다 — 하루에 세 번 봤다(`blend` 랭킹, 눌림 3%, breadth 0.6).

in-sample 최적값은 "그 구간에서 뭐가 좋았나"를 말할 뿐, "다음 구간에서 뭐가 좋을까"를 말하지 않는다.

```
[학습 4년] → 규칙 선택 → [검증 1년, 한 번도 안 봄] → 성과 기록
     └ 1년 뒤로 밀어서 반복
```

## 하니스가 구조적으로 막는 것

오늘 실제로 겪은 결함들을 **어서션으로** 막는다. 안전장치가 죽어 있으면 없느니만 못하므로
(통과했다는 사실이 근거로 쓰이기 때문에) **일부러 깨뜨려 발동을 확인**했고 회귀테스트 20건으로 잠갔다.

| 겪은 결함 | 막는 장치 |
|---|---|
| `--start` 무시로 구간이 조용히 잘림 | `_assert_window` — 시뮬한 영업일 수를 요청 구간과 대조 |
| 학습/검증 누수 | `_assert_no_leak` — 검증구간 밖 진입이 하나라도 있으면 실패 |
| 폴드 경계 오류 | `_assert_folds` — 학습 종료 < 검증 시작 엄격 검사 |
| 워밍업 부족이 구간 축소로 둔갑 | 데이터는 전 구간 로드, **매매 판단만** `sim_from/sim_to` 로 제한 |
| 사후 선택("이게 좋네") | 후보 격자 `GRID` 와 선택 규칙 `select()` 를 **모듈 상수/함수로 사전 고정** |
| 생존편향 절대값 오독 | 결과를 **항상 동일 유니버스 동일가중 벤치마크와 함께** 출력 |

선택 규칙은 사람이 개입하지 않는다. 동점이면 `GRID` 선언 순서를 따르므로 재현 가능하고,
학습구간이 전부 손실이어도 규칙대로 '가장 덜 나쁜' 것을 고른다 — 실제 운용의 그 시점 판단이 그렇다.

### 읽는 법

**1. 현행 청산 사다리는 8개 폴드에서 한 번도 선택되지 않았다.**
후보에 넣어뒀는데(`현행 사다리·슬롯5`, `·슬롯20`) 학습구간 성적이 매번 뒤졌다.
2026-08-28 in-sample 진단(ATR 트레일이 범인)의 **독립적 확인**이다. 사람이 고른 게 아니라
기계적 선택 규칙이 매번 트레일 없는 쪽을 뽑았다.

**2. 그러나 세부 파라미터는 불안정하다.** 뽑힌 규칙이 폴드마다 4종류로 갈린다
(MA120·슬롯5 ×3 / MA120·슬롯20 ×2 / MA200·슬롯20 ×2 / MA120+시간120 ×1).
"MA120·슬롯20 이 최적" 같은 주장은 여전히 근거가 없다. 견고한 것은 **트레일 제거**뿐이다.

**3. 재개 조건 미충족.** OOS 누적이 벤치마크에 못 미친다(+363.9% vs +475.0%, 상회 3/8).

### 골대를 옮기지 않는다

전략의 폴드별 MDD 는 14~24% 로 낮고, 12년 벤치마크 MDD 는 51% 였다. 위험조정으로 보면
경쟁력이 있어 보인다 — **그러나 이것을 근거로 "통과"라고 하지 않는다.**
판정 기준은 결과를 보기 **전에** 선언했고(누적수익 벤치마크 초과), 결과를 본 뒤 기준을 바꾸는 것이
바로 이 프로젝트가 반복해 온 실패 방식이다.

위험조정 비교를 하려면 **다음 검증에서 그 기준을 미리 선언하고** 벤치마크의 폴드별 MDD 도
같은 방식으로 측정해야 한다. 그건 별도 작업이다.

## 결론

- 신규진입 **정지 유지**(`TREND_ENTRY_HALT=true`).
- 확정된 것 하나: **ATR 트레일은 제거 대상이다.** in-sample 진단과 워크포워드가 독립적으로 일치.
- 확정되지 않은 것: 어떤 청산으로 대체할지, 슬롯 몇 개인지. 폴드마다 답이 달라진다.
- 다음: 위험조정 기준을 **사전 선언**한 뒤 재검증. 그 전엔 어떤 파라미터도 라이브에 넣지 않는다.
