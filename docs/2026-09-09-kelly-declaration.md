# 켈리 기준 사전 선언 — 감시용, 사이징 아님 (2026-09-09)

## 왜 지금 선언만 하는가

채택 구성(`EXITS=ma,hold`, 2026-08-28) 이후 **실제 진입이 0건**이다 — 레짐 게이트가
38영업일째 막고 있다. 잴 표본이 없다.

표본이 생긴 **뒤에** 임계를 정하면 숫자를 보고 기준을 맞추게 된다. 그게 이 프로젝트가
반복해서 틀린 방식이다([08-27 `blend` 채택](2026-08-27-backtest-window-defect.md)).
그래서 계산과 기준을 지금 코드 상수로 고정하고, 실행은 표본이 찰 때까지 "표본 부족"만 출력한다.

## 켈리를 실제로 풀어본 결과

교과서 `f* = (bp−q)/b` 는 우리 상황에 안 맞는다 — "지면 전액 손실" 전제인데 우리 최악
거래는 **−10.4%** 다(하드손절이 바닥). 실제 분포로 `E[log(1+f·R)]` 를 직접 최대화했다.
표본: 12년 시점별 유니버스, 채택 구성, 3,194건.

| | f* | 성장률/거래 |
|---|---|---|
| 이항 근사 | 18.4% | — |
| **실제 분포** | **133.0%** | +4.39% |
| 현행 슬롯당 5% | — | +0.455% |

133% 는 레버리지 권고다. 손실이 −10% 에서 잘리니 f=1 이어도 파산이 불가능해 나오는 값이다.

### 이 숫자를 사이징에 쓸 수 없는 이유

**① 상위 5% 거래가 결과를 지배한다**

| 제거 | f* | 성장률 |
|---|---|---|
| 없음 | 133.0% | +4.39% |
| 상위 10건 | 126.5% | +3.77% |
| **상위 160건(5%)** | **27.9%** | **+0.14%** |

3,194건으로 잰 것 같지만 실질적으로 160건이 정한다. 그 160건엔 생존편향 잔재가 남아 있다
(PIT 풀이 현재 시총 상위 350).

**② 구간마다 10배 흔들린다**

```
1/4분기 106.8%   2/4분기 29.0%   3/4분기 40.6%   4/4분기 285.0%
전반 69.6%   후반 178.4%
```

파라미터가 아니라 동전 던지기다. `blend` 랭킹을 철회한 이유와 같은 성질이다.

**③ 켈리는 순차 베팅 전제** — 우리는 슬롯 20 을 동시에, 전부 KOSPI 대형주 추세추종으로
들고 있어 강하게 상관된다. 상관 ρ 보정: ρ=0.3 → 총 397%, ρ=0.5 → 253%, ρ=0.7 → 186%.

**④ 추정오차에 치명적** — 승률 5%p 하락에 f* 가 133% → 14.6% 로 9배 급락한다.

## 우리는 이미 켈리가 권하는 자리에 있다

총노출 100% 를 ρ 보정 켈리와 비교하면:

| ρ 가정 | 켈리 총노출 | 우리 비율 |
|---|---|---|
| 0.3 | 397% | 0.25 켈리 |
| 0.5 | 253% | 0.40 켈리 |
| 0.7 | 186% | 0.54 켈리 |

**1/4 ~ 1/2 켈리** — 추정오차를 감안할 때 표준적으로 권장되는 범위 그대로다.
그리고 방향이 중요하다: 우리는 **과베팅이 아니라 저베팅** 쪽이다. 성장률 곡선은 비대칭이라
f* 를 넘기면 급격히 나빠지고(2×켈리 +2.03% < 풀켈리 +4.39%) 못 미치면 완만히 손해다.
추정을 못 믿을 때 있어야 할 쪽에 있다.

→ **켈리를 사이징 규칙으로 융합하지 않는다.**

## 선언 — 감시 지표로서의 기준

`scripts/kelly_monitor.py` 의 모듈 상수로 고정했다(변경 시 `tests/test_kelly_monitor.py` 가 깨진다).

| 항목 | 값 | 근거 |
|---|---|---|
| 주 지표 | **전체 분포 f\*** | 절단본은 꼬리를 지우는 것 = 추세추종의 엣지를 지우는 것 |
| 임계 | f\* < 총노출 → 과베팅 | 노출 = 슬롯수 × 종목당% |
| 지속 요건 | `PERSIST_N=2` 회 연속 | f\* 가 10배 흔들리므로 단발 교차는 무시 |
| 표본 요건 | `MIN_TRADES=50` | 그 전엔 **f\* 를 계산조차 하지 않는다** |
| 대상 | `ADOPTED_SINCE=2026-08-28` 이후 청산 | 이전은 청산 사다리가 달라 분포가 다르다 |
| 스트레스 참고 | 상위 5% 절단 f\* | **판정에 미사용** — 함께 출력만 |
| 행동 | 알림뿐 | 자동 축소 없음. 노출 변경은 워크포워드 재검증 |
| 폐기 조건 | 12회 측정에서 f\* 최대/최소 비 > 5배 | 쓸모없는 지표를 남겨두면 로그만 오염된다 |

### 표본 50건의 한계를 미리 적어 둔다

이 분포는 상위 5% 가 결과를 지배한다. 50건이면 그 5% 가 2~3건이다.
**50 은 "판정을 시작해도 될 최소"지 "충분"이 아니다.** 판정할 때 표본 수를 함께 읽을 것.

### 절단 f* 를 판정에 쓰지 않는 이유

현재 절단 f* 는 27.9% 로 이미 총노출 100% 보다 낮다. 그걸 임계로 쓰면 **켜자마자 상시
경보**가 된다. 매일 뜨는 경고는 아무도 읽지 않는다 — 오늘 아침에 고친 8030 오탐과 같은
종류의 실패다.

## 주문에 관여하지 않는다

`kelly_monitor.py` 는 주문·상태 경로를 import 하지 않고, 데몬도 이 모듈을 부르지 않는다.
둘 다 테스트로 잠갔다(`test_monitor_never_touches_orders`, `test_monitor_is_not_imported_by_daemon`).

자동 사이징으로 바꾸려면 그건 **전략 변경**이다 — 워크포워드 격자에 후보로 넣어 OOS 로
검증해야 한다. 인샘플 켈리 값으로 실계좌 사이징을 바꾸는 것은 08-27 에 걷어낸 패턴이다.

## 언제 다시 보나

레짐 게이트가 풀려 진입이 재개되고 청산 50건이 쌓인 뒤. 현재 KOSPI 가 MA60 보다 약 9%
아래라 최소 몇 주가 걸린다. 그때 `python scripts/kelly_monitor.py` 를 돌리면 위 기준
그대로 판정한다 — 그 시점에 기준을 새로 정하지 않는다.

## 정정 (2026-09-29) — 판독 로직 결함, 기준은 불변

`adopted_returns()` 가 `closed`·`exit_date` 필드를 찾았는데, 데몬이 쓰는 청산 기록은
`type: "exit"` + `ts` 형식이라 둘 다 없다. 운영 저널의 청산 22건 중 **0건**을 읽었다.
채택 이후 청산이 아직 없어 "0/50" 출력 자체는 우연히 맞았지만, 09-30 예정된 첫 청산부터 틀렸을 것이다.

- **읽는 방법만 고쳤다. 위 표의 기준(상수)은 하나도 바뀌지 않았다** — 표본을 본 뒤 기준을 고친 것이 아니다.
- 한 거래를 나눠 판 경우(구 사다리의 부분익절) 거래 1건으로 수량 가중 합산한다. 켈리의 베팅 단위는 거래다.
- 테스트가 가짜 리스트로 계산만 검증해 저장 형식 경계를 한 번도 지나지 않았다. 이제 세 가지로 잠근다:
  데몬의 쓰기 함수(`journal_append`)로 기록하고 같은 읽기 함수로 읽는 테스트 · 쓰기 쪽 형식이 바뀌면
  깨지는 테스트 · 운영 저널에 청산이 있으면 판독 결과가 0 이 아니어야 한다는 테스트.
- 실행 출력에 `저널 판독: 전체 N거래` 를 함께 찍는다 — 판독이 다시 깨지면 0 으로 드러난다.
  정정 직후 출력: `전체 22거래 · 채택 이전 22거래 제외`.
