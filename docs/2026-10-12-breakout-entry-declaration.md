# 진입 타점 A/B 사전 선언 — 눌림 vs 돌파 (2026-10-12)

**상태: 측정 전 선언.** 이 문서와 코드 상수(`walkforward_trend.py` 의 `ENTRY_*`,
`backtest_trend.py` 의 `report_entrytest`)는 돌파 진입의 성과를 **한 번도 보지 않은 상태**에서
커밋한다. 결과는 맨 아래 "결과" 절에 덧붙이고, 기준은 고치지 않는다(작업 규칙 1).

## 질문

구루 다수(터틀 20/55일 돌파 · 오닐 베이스 돌파 · 미너비니 VCP · 다바스 박스)는 **돌파**를 산다.
우리는 상승 추세 안의 **눌림**(MA20 ≤ 가격 ≤ MA20×1.12)을 산다. 진입을 돌파로 바꾸면 나은가.

## 측정 전에 이미 아는 것 (성과 미열람)

12년 시점별 유니버스 진입 3,161건의 **진입 시점 위치만** 셌다. 수익률을 위치별로 나누는 것은
그 자체로 돌파 성과를 엿보는 것이라 하지 않았다.

| 진입 시점 위치 | 비율 |
|---|---|
| 20일 고가 돌파일(터틀 S1 신호) | 28.2% |
| 55일 고가 돌파일(터틀 S2 신호) | 21.1% |
| 20일 고가 3% 이내 | 57.5% |
| 52주 고가 5% 이내 | 39.3% |
| 52주 고가 25% 이내(미너비니 조건) | 91.9% |

진입가 중앙값은 직전 20일 고가 대비 **-2.2%**. 현행 진입은 '깊은 눌림'이 아니라 '과열 추격 금지'에
가깝고, 4건 중 1건은 이미 돌파일이다. **바꿔도 달라지는 것은 나머지 ~70%** 다.

## 비교 대상

### 진입 모드 (`signals.TrendConfig.entry_mode`)

| 모드 | 타점 |
|---|---|
| `pullback` (현행) | MA20 ≤ 종가 ≤ MA20×1.12 |
| `breakout20` | 종가 > 직전 20일 최고가(당일 제외) — 터틀 S1 |
| `breakout55` | 종가 > 직전 55일 최고가 — 터틀 S2 |

공통(모든 모드 동일): 종가 > MA60 · 종가 > MA120 · RS(60일) > KOSPI · 거래량 ≥ 20일 평균 ·
레짐/breadth 게이트 · composite 랭킹 · 익일 시가 진입 · 청산/사이징. **타점만 바꾼다.**

터틀은 장중에 그 가격을 찍는 순간 샀지만, 이 시스템은 종가로 신호를 보고 다음 날 사므로
종가 확정 돌파만 센다.

**혼합형(눌림 + 52주 고가 근접)은 뺐다.** 미너비니 기준(25% 이내)은 현행 진입의 92%가 이미
충족해 사실상 현행과 같고, 더 좁은 임계(5%·10%)는 근거 없이 고른 숫자라 후보만 늘린다.

### 절차 (`python scripts/walkforward_trend.py --entry-ab`)

각 절차는 자기 메뉴에서 **매년 학습 4년으로 하나를 고르고** 다음 1년에 검증한다(현행 연간
재선택과 같은 절차). 돌파 메뉴는 GRID 의 청산·슬롯 7종을 그대로 복제하고 진입만 바꿨다.

| 절차 | 메뉴 | 묻는 것 |
|---|---|---|
| **A** | 눌림 7 (= GRID) | 기준점 — 현행 |
| **B** | 눌림 7 + 돌파20 7 + 돌파55 7 = 21 | 고를 수 있게 하면 나은가 |
| **C20** | 돌파20 7 | 바꾸면 나은가 (질문 그대로) |
| **C55** | 돌파55 7 | 〃 |

## 판정 기준 — 도전자 X 가 A 를 대체하려면 **전부** 충족

| | 기준 | 선언값 |
|---|---|---|
| ① | 기존 절대 기준(08-28 선언 그대로) | MDD ≤ 벤치마크×0.5 · MAR ≥ 벤치마크 · 플러스 연도 ≥ 60% |
| ② | MAR 개선 | MAR(X) ≥ MAR(A) **+ 0.10** |
| ③ | 위험 상한 | MDD(X) ≤ MDD(A) **+ 3.0%p** |
| ④ | 폴드 우위 | 검증연도 수익이 A 보다 **높은** 폴드 ≥ **60%**(8폴드면 5) |
| ⑤ | PIT 가드 | 시점별 유니버스 12년 거래당 백테스트에서 X 가 쓰는 돌파 규칙의 **기대값 ≥ 눌림 그리고 PF ≥ 눌림** |

**⑤가 필요한 이유.** 워크포워드 하니스의 유니버스는 **현재** 시총 상위 100 이라 생존편향이
있다. 전략과 벤치마크가 공유하므로 둘의 비교는 유효하지만, **강세를 사는 돌파가 그 편향의
수혜를 눌림보다 더 받을 수 있다.** ①~④만으로는 '돌파가 낫다'와 '살아남은 종목이 돌파를
많이 했다'를 가르지 못한다.

- 여럿이 통과하면 OOS MAR 이 가장 높은 것. 이 선택 자체가 OOS 를 보는 것이므로 채택 수치는
  낙관 편향을 갖는다고 함께 적는다.
- **하나도 통과 못 하면 현행 유지.** 돌파 기간(30일·40일 등)을 바꿔 다시 재지 않는다 —
  그렇게 하면 기준을 통과할 때까지 변형을 찾는 것이 된다.

## 측정 조건 (규칙 2: 검증 조건 = 운용 조건)

```bash
# ①~④ — 08-28 재검증과 같은 예탁·구간
TREND_BT_EQUITY=3852844 python scripts/walkforward_trend.py --entry-ab
# ⑤ — 시점별 유니버스(기본 on)·라이브 미러, 워크포워드와 같은 종료일
python scripts/backtest_trend.py --entrytest --start 2015-06-01 --end 2026-08-25
```

- 데이터 2015-01-01 ~ 2026-08-25(`DATA_END` 고정 — 08-28 기준선과 같은 구간), 학습 4년/검증 1년,
  선택 기준 MAR, 노출 1.0, 왕복 비용 ≈0.43%, 익일 시가 진입.
- **재현성 점검**: A 는 독립 실행(`walkforward_trend.py`, 같은 예탁)과 숫자가 같아야 한다.
  다르면 하니스 결함이다. 08-28 공표치: 누적 +234.8% · MAR 0.96 · MDD 18.4% · 플러스 7/8.
  선언 직전 독립 실행으로 **공표치 그대로 재현됨**을 확인했다(돌파 코드 반영 전, 6분).

## 알려진 한계

1. **통계적 유의성은 보일 수 없다.** 8폴드, 연 변동 ~20% → MAR 표준오차 ~0.4. ②의 +0.10 은
   '유의한 개선'이 아니라 '바꿀 만한 근거가 있는가'의 최소선이다.
2. **진입 시각.** 백테스트는 익일 시가, 라이브는 11:00 이다. 돌파 다음 날 오전에 추가로 오르는
   경향이 있다면 라이브 체결가가 백테스트보다 불리해, **이 검증은 돌파에 유리하게 편향**된다.
   12년치 분봉이 없어 측정할 수 없다. 채택하면 `trend_paper` 대조로 체결 괴리를 감시한다.
3. **B 메뉴 21개**는 GRID ≤ 12 원칙(`test_grid_is_small_enough`)의 예외다. 후보가 많을수록
   학습구간 과적합이 커지는데, 그 비용도 OOS 성적에 그대로 반영되므로 B 의 판정은 공정하다.
   GRID 자체는 바꾸지 않는다(연간 재선택 불변).
4. 거래당 백테스트(⑤)는 신호일마다 1거래(같은 종목 연속 신호 포함)라 포트폴리오 성과가 아니다.
   방향(돌파 ≥ 눌림인가)만 본다.

## 채택되면 할 일 (지금은 하지 않는다)

`TREND_ENTRY_MODE` 설정 추가 · GRID 갱신 + 연간 재선택 · 라이브 스크린/알림 문구('눌림권') 점검
· 설정 스냅샷 테스트. 채택되지 않으면 [RS 정의 A/B](2026-08-28-rs-definition-ab.md) 처럼
막다른 길로 기록한다.
