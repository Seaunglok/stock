## 첫 실행에서 배운 것 (11-06)

- 네이버 검색 API 는 연속 호출하면 끊긴다 → 호출 사이 0.15초 + 429 면 쉬었다 다시. 실패 이름표에 HTTP 코드를 남긴다.
- 한 번에 최신 100건 · 최대 1,000건 — 11-06 은 '코스피'·'반도체'·'삼성전자'·'SK하이닉스'가 하루 1,000건을 넘었다.
  창 시작까지 페이지를 넘기고, 그래도 못 닿으면 **'+' 표시**(실제보다 적게 센 주제).
- 대표 제목을 '가장 최근 기사'로 고르면 본문에만 키워드가 걸린 기사(비트코인 등)가 뽑힌다 → 제목에 주제어가 든 기사 우선.
  '금리'는 예·적금 상품 기사까지 잡혀 '기준금리'로 좁혔다.
- **수급 기준·단위를 모은 뉴스로 대조해 확정했다.** ka10051 금액 = 억원. 기준은 KRX(stex_tp 1) — 11-06 기관 +1.71조가
  보도('기관 1.7조 샀다')와 같다. 처음 쓴 통합(3) = KRX + 대체거래소(NXT, 외국인 +462억)라 외국인 −2.64조로 작게 나왔다.
  보도의 외국인 −2.77조(장 마감 직후 잠정)와 KRX 확정 −2.69조의 차이는 시간외 거래 — 그래서 확정치는 다음 날 아침에 받는다.
- **지난 날짜도 받을 수 있다** — ka10051 base_dt 로 2010-01-04 까지 확인(2020-03-19 코로나 폭락일 외국인 −6,179억).
  '다시 못 구하는 자료'라는 전제는 이 수급엔 약하다. 대신 **과거 이력을 한꺼번에 채울 수 있다**(백로그).
- 11-06 은 첫날이라 22시에 수동으로 모았다(아침 묶음의 뉴스 창이 길다). 정규 실행은 11-09(월)부터.
