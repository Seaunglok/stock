# Claude 뉴스 판단 일지 — 앞으로만 시험 (2026-11-25 ~, 판정 120거래일)

운용자(11-25): "챗gpt 나 제미나이로 투자 많이 한다고 하는데 나는 클로드만 사용하고 있어. 더 분발할 필요가 있어"
→ Claude 뉴스 판단을 정직하게 시험하자는 제안에 **"시작하자"**.

선언·코드: [`scripts/llm_news.py`](../scripts/llm_news.py)(docstring 이 정본) · 시험 `tests/test_llm_news.py` ·
시험 횟수 장부 `lab_trials` +2(L1·L2).

## 왜 이렇게 재나

- 11-19 평가([시스템 평가](2026-11-19-system-review.md))에서 본 연구들: 데이터 누수를 막고 시험 횟수를 보정해 재면, 언어 모델이 찾은
  매매 전략은 무너졌다. 근본 이유는 **모델이 과거 시장을 이미 읽었다**는 것 — 과거로 백테스트하면 답을 아는 채로 시험을 본다.
  ChatGPT·Gemini·Claude 모두 같다.
- 그래서 **모델이 배운 적 없는 앞으로의 날로만** 잰다(Opus 5.5 지식 마감 2026-06 — 기록은 2026-11-25 부터).
  매매 판단에는 넣지 않는다(주문·리그 비중에 안 쓴다). 통과하면 그때 공격형 리그 앞으로만 멤버 후보.
- 비교 상대가 있다: 이미 기록 중인 **N2**(헤드라인 부정 단어 비율 — 규칙 기반, [뉴스·경제 지표 일지](2026-11-16-flows-news-lab.md)).
  L1 은 N2 와 같은 잣대라 "Claude 가 읽으면 단어 세기보다 나은가"가 그대로 나란히 보인다.

## 매일 하는 일 (판단 배치 맨 끝, 시장 일지 close 뒤)

1. 그날 시장 일지(`data/market_journal/<날짜>.json`)에서 **정해진 규칙**으로 글을 만든다(같은 파일이면 글자 하나 다르지 않다):
   주요사항보고 공시 제목 전부 · 오늘부터의 일정 · 대표 제목(아침·장중) · 장중 뉴스 최신 300 · 아침 뉴스 최신 100(제목 중복 제거).
   가격·수급 숫자는 따로 주지 않는다. 11-25 기준 제목 410개 · 약 2만 1천 자.
2. headless `claude -p` 로 묻는다 — **모델 고정 `claude-opus-5-5`** · 도구 없음 · MCP 없음 · 설정·훅·플러그인 없음 ·
   프로젝트 밖 폴더(`%TEMP%\llm_news_cwd` — 지침·메모리가 끼지 않는다) · 세션 저장 안 함 · JSON 스키마로만 답.
   11-25 시험 호출: 받은 지시는 역할 지시뿐(훅·메모리·CLAUDE.md 없음)이라고 답했다.
   **인증은 구독 로그인(정액제)만** — 자식 환경에서 `ANTHROPIC_API_KEY` 등 API 인증 변수(`API_AUTH_ENV`)를 뺀다(11-26, 아래 사고).
3. 답: `direction` −2 … +2(다음 5거래일 = 내일 시가 → 6거래일째 시가 코스피) · `risk` 높음/보통/낮음(그 안에 −5% 이상 하락 위험) ·
   `reason`. → `data/llm_news/daily.csv` 한 줄(+ `.bak`), 넣은 글 `data/llm_news/inputs/<날짜>.txt`(SHA256 을 줄에 남김),
   답 원문 `inputs/<날짜>.answer.json`(어느 모델이 답했는지·비용 — 11-26 부터, 첫 기록 11-25 는 줄만).
4. 텔레그램 「🤖 [Claude 뉴스 판단] MM-DD — 다음 5거래일 코스피 ±n(…) · 큰 하락 위험 … · 이유 (기록 n/120 — 판정 전)」.

**지키는 것**: 그날(d) 안에만 묻는다(다음 날 묻거나 지난 날을 채우지 않는다) · 같은 날 한 번만 · 거래일만(잠정 수급이 있는 날) ·
답한 모델이 다르거나 답 형식이 어긋나면 기록하지 않는다(대체 모델로 채우지 않는다).

**실패하면**: 「⚠️ [Claude 뉴스 판단] 기록 실패 — …」 일반 알림. **그날 안에** `python scripts\llm_news.py` 를 다시 돌리면 기록된다.
다음 날엔 묻지 않는다 — 그날은 빈 날로 남는다(빈 날은 결과와 무관하게 생기므로 판정을 기울이지 않는다).
흔한 원인: headless claude 로그인 만료(11-19 Notion 자동 기록과 같은 것 — 터미널에서 `claude` → `/login`).
「Credit balance is too low」·「Invalid API key」면 API 키가 자식에게 넘어간 것 — `child_env` 가 빠졌는지 본다(11-26).

## 판정 (선언 — 판정일 전엔 결과를 보지 않는다)

| 가설 | 해당 날 | 통과(전부) |
|---|---|---|
| L1 | direction ≤ −1 | 해당 날 ≥ 15 · 뒤 5일 평균이 기록 기간 전체 평균보다 0.5%p 이상 약함 · 하락 적중 ≥ 기저율 + 10%p · **구간 섞기 p ≤ 0.01** |
| L2 | direction ≥ +1 | 해당 날 ≥ 15 · 0.5%p 이상 강함 · 상승 적중 ≥ 기저율 + 10%p · **구간 섞기 p ≤ 0.01** |

- 앞의 셋은 N2 와 같은 잣대. **구간 섞기 검정**을 더했다: 판단 열을 10거래일 구간으로 잘라 순서만 1만 번 섞고(시드 고정), 같은 차이
  이상이 나오는 비율. 판단이 며칠씩 몰리는 것·뒤 5일 수익이 겹치는 것을 구간 안에 그대로 둔 채 재는 우연 기준이다
  (날짜별로 섞으면 뭉침이 깨져 너무 쉽게 통과하고, 순환 이동은 120일이면 경우가 100개 남짓이라 0.01 에 못 닿는다 — 선언 전에 바꿈).
  0.01 = 뉴스 가설 묶음(N1~N3 · L1~L2) 5개 본페로니 단측 5%.
- 판정일: 기록 120거래일(2027-05 무렵, Flow Task). 해당 날이 모자라면 기준을 낮추지 않고 미룬다.
- **공격형 리그 멤버 LLM-N1(11-25 운용자 "바로 후보로")**: 이 판단으로 실제로 굴린 그림자 기록 — 부정이면 인버스·긍정이면 KODEX200 을
  다음 날 시가에 5거래일, 50만원·비용·정수 주식. L1·L2 와 따로 판정(120거래일 + 완료 거래 10) — [공격형 트랙 LLM-N1](2026-10-28-aggressive-track.md).
  리그 알림에 매일 성적이 보이지만, 판정 전엔 규칙을 바꾸지 않는다.
- 보고만(판정 아님): L1 과 N2 같은 기간 뒤 5일 평균 · risk 높음 날 뒤 5일 최저 · 방향 점수와 뒤 5일 순위 상관.
- 시험이 맞게 짜였는지(`tests/test_llm_news.py`): 판단 뒤에 실제로 빠지는 가짜 시장이면 통과, 같은 수를 시장과 무관하게 찍으면 탈락,
  가장 약한 10일에 몰아 찍은 판단은 p 가 작아지지 않는다.

## 11-26 사고 — API 계정으로 과금되고 있었다 (고침)

- **증상**: 11-26 15:54 「기록 실패 — claude 오류: success Credit balance is too low」. 같은 배치의 Notion 자동 기록(역시 headless claude)은 성공.
- **원인**: `.env` 에 `ANTHROPIC_API_KEY` 가 있다(옛 Claude 에이전트용, 운용 코드는 안 씀). `llm_news.py` 가 알림용으로 `ops_base` 를
  부르면 `trend_config` 가 `.env` 의 모든 키를 환경에 올리고, 자식 `claude -p` 가 그것을 물려받는다. claude 는 환경에 API 키가 있으면
  **구독 로그인보다 그 키를 먼저 쓴다** → 토큰당 API 과금(구독과 별개 계정) → 그 계정 잔액이 떨어져 실패. 11-25 첫 기록($0.19)도 이 길로 나갔다.
  Notion 기록은 `i3_notion.cmd` 가 cmd 에서 claude.exe 를 바로 불러 `.env` 를 거치지 않으므로 처음부터 구독으로 돌았다.
- **확인(진짜 claude)**: 가짜 키를 넘기면 「Invalid API key · Fix external API key」(로그인 토큰 없음) — 키가 먼저다. 고친 `ask()` 는
  부모 환경에 `.env` 키가 있어도 구독으로 답한다(답 원문 `credential_expires_at` 이 찍힘 · 모델 `claude-opus-5-5`).
- **고침**: `child_env()` — 자식 환경에서 `API_AUTH_ENV`(`ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`·`ANTHROPIC_BASE_URL`·Bedrock/Vertex/Foundry
  전환 변수)를 뺀다. 테스트는 진짜 자식 프로세스로 확인하고, 옛 길(환경 그대로)은 같은 과금 오류로 실패하는 것까지 본다.
- **그날 기록**: 16:2x 에 이번 실행만 키를 빼고 재실행 → 2/120 기록(같은 날 안 · 같은 입력 규칙 — 앞으로만 원칙 안).
- 시험 조건은 그대로다 — 같은 모델·같은 글, 청구 경로만 바뀌었다.

## 하지 않는 것

- 결과가 좋아 보여도 판정일 전에 매매에 쓰지 않는다 · 판정 기준을 고치지 않는다(고치면 이 시험은 무효).
- 프롬프트·모델·넣는 글 규칙을 바꾸지 않는다 — 바꾸면 그 날부터 다른 시험(새 선언·새 시험 장부 행).
- 지난 날을 다시 묻지 않는다(모델 업데이트·뒤늦은 기사로 미래를 아는 상태가 된다).
