# 그림자 원장 (Shadow Ledger) — 진입하지 않은 후보의 사후 추적

> **한 줄**: 게이트가 막은 종목이 이후 어떻게 됐는지 기록해, "그 게이트가 옳았나"를 **숫자로** 판정한다.
>
> 구현: [scripts/shadow_ledger.py](../scripts/shadow_ledger.py) · 원장: `data/trend_follow/shadow.jsonl`

---

## 1. 왜 만들었나

2026-08-05, 08:50 스크리닝에서 삼성에스디에스(018260)가 5게이트 전부 통과·점수 44.0으로 후보에 올랐다.
11:00 진입 시각에 **슬롯 만석(5/5)** 으로 스킵됐고, 그날 종가는 **+4.78%** 였다.

문제는 손실이 아니라 **기록이 없다는 것**이었다. 그때까지 로그에 남은 건 한 줄뿐:

```
[NOTIFY] ℹ️ 추세추종 진입: 후보 3 슬롯 0 — 진입 없음
```

`events.jsonl` 에는 이벤트조차 없었다. 이 상태로는 몇 달이 지나도 다음 질문에 답할 수 없다.

- 레짐 게이트가 실제로 손실을 막고 있나, 수익 기회를 버리고 있나?
- `MAX_POS=5` 가 적정한가, 좋은 후보를 계속 놓치고 있나?
- breadth 임계값을 낮춰야 하나?

**게이트는 자기가 막은 것의 결과를 볼 수 없다.** 그래서 별도로 봐 주는 장부가 필요하다.

이건 2026-08-03 회고의 교훈 #1("백테스트 통계는 레짐별로 쪼개 봐야 한다")의 연장선이다 —
그때는 과거 데이터를 쪼갰고, 이건 **앞으로의 데이터를 처음부터 쪼개서 쌓는다**.

## 2. 무엇을 어떻게 재나

### 측정 원칙 — 손익비 기하로 판정

단순 수익률이 아니라 **진입 시점의 손절/목표**로 판정한다. 안 그러면 "차단된 종목이 +3% 올랐다"
같은 무의미한 비교가 된다(우리는 그 +3%를 온전히 먹지 못한다).

> ⚠️ **라이브 청산규칙 전체가 아니다.** 반영되는 건 **초기 손절 · 첫 목표(1:3)** 둘뿐이다.
> ATR 트레일 래칫 · 30% 부분익절 · MA120 이탈 · 외인 순매도 · 시간청산(60영업일)은 **미반영**.
> 즉 이 원장은 "그 자리에 들어갔다면 손절과 첫 목표 중 뭐가 먼저였나"를 잰다 —
> 게이트 판정에는 충분하지만 **실제 손익 추정치는 아니다**(트레일이 있으면 대개 -1R보다 덜 잃고,
> 목표 도달분은 +3R보다 더 벌 수 있다).

| 결과 | 의미 |
|------|------|
| **손절 선행** (stop) | 게이트가 **손실을 막았다** → -1.0R |
| **목표 선행** (target) | 게이트가 **수익을 놓쳤다** → +3.0R (손익비 1:3) |
| **미결** (open) | 20영업일까지 미도달 → 마지막 종가 기준 R |

### 가상 진입가

우선순위: **실제 체결가(`entry_actual`, taken 한정) → 그날 진입 시각의 5분봉 시가 → 그날 종가**.
어느 쪽을 썼는지는 `entry_src` 필드(`actual`/`minute`/`close`)에 남는다.
→ [collect_minute_bars.py](../scripts/collect_minute_bars.py) 가 매일 수집하는 분봉을 재활용.

진입 시각은 **그날 적용되던 값**을 쓴다 — 07-31 이전은 09:30, 08-03 부터 11:00
(`_ENTRY_TIME_HISTORY` 이력 테이블 + 신규 레코드의 `entry_time` 스탬프).
현재 설정값을 과거에 소급하면 다른 시각 가격으로 재는 셈이 된다.

손절/목표는 라이브와 **동일한 공식**: `stop = entry − ATR_K×ATR`, `target = entry + RR×(entry−stop)`.

### 판정 구간

손절/목표 도달은 **익일봉부터** 본다 — 진입일의 고/저가는 11:00 이전 구간을 포함해 왜곡되기 때문.
같은 날 손절·목표를 모두 스치면 보수적으로 **손절 선행**으로 본다.

### 대조군

실제 진입분도 `reason="taken"` 으로 같은 방식으로 기록한다.
**같은 자로 재야 비교가 성립한다** — "차단분 -0.33R vs 진입분 -0.51R" 같은 문장이 그래서 가능하다.

`taken` 은 손절·목표가 **실제 체결가** 기준으로 잡혀 있으므로 평가 진입가도 실체결가(`entry_actual`)를
쓴다 — 진입가만 프록시로 바꾸면 `risk = entry − stop` 이 뒤틀려 R 이 무의미해진다(§9 D1).

## 3. 기록되는 사유

`trend_follow.py` 의 모든 종착 스킵 지점에 훅이 걸려 있다.

| reason | 라벨 | 발생 지점 |
|--------|------|----------|
| `taken` | 실제 진입(대조군) | `_buy_one` 체결 성공 |
| `no_slot` | 슬롯 만석 | `phase_entry` 슬롯 0 · 매수 루프 중 소진 · `_try_pending` |
| `regime` | 레짐 게이트(KOSPI<MA60) | `phase_entry` |
| `circuit` | 서킷브레이커 | `phase_entry` |
| `sector_gate` | 주도섹터 게이트 | `_apply_sector_rally` (SECTOR_GATE=true 시) |
| `size_zero` | 사이징 0주(자본 제약) | `_buy_one` qty<1 |
| `cutoff` | 진입마감 경과 | `_try_pending` |
| `no_rebound` | 장중 미반등 | `phase_exit` |
| `already_held` | 이미 보유(물타기 금지) | `_buy_one` |
| `order_reject` | 주문 거부 | `_buy_one` |
| `hist_blocked` | 과거 미진입(소급·사유미상) | `--backfill` 로 생성 |

> **breadth 게이트는 별도 사유가 없다** — 09:30 차단은 종착이 아니라 *보류*(장중 회복 시 진입)이기
> 때문. 끝내 못 사면 `no_rebound` 또는 `cutoff` 로 잡힌다.

훅 호출 지점은 `trend_follow.py` 에 **12개소**(사유 10종 + 소급 1종). `grep -n shadow_record` 로 확인.

**중복 방지**: 같은 날 같은 종목은 1회만 기록한다(먼저 걸린 사유 보존). 10분 폴링 경로가
같은 후보를 반복 기록하는 것을 막는다. **예외: `taken` 은 기존 레코드를 교체한다** —
오전에 `size_zero` 로 막혔다가 장중 재시도로 체결되는 경로가 있어, 안 그러면 실제로 산 종목이
'차단됨'으로 오분류되고 대조군 표본이 사라진다(§9 D5).

**절대 매매를 막지 않는다**: `record()` 는 내부에서 모든 예외를 삼킨다. 원장 기록 실패가 주문을
방해해선 안 된다.

## 4. 사용법

```bash
# 사후 성과 갱신 (장 마감 후 — 데몬이 15:20 exit phase 에서 자동 호출)
python scripts/shadow_ledger.py --update

# 평가 로직을 고쳤을 때 — 확정분 포함 전량 재평가
python scripts/shadow_ledger.py --recompute

# 리포트 (사유별 집계 + 월별 분해 + 판정)
python scripts/shadow_ledger.py --report
python scripts/shadow_ledger.py --report --detail        # 레코드별 상세
python scripts/shadow_ledger.py --report --days 30       # 최근 30일만

# 갱신 + 리포트 한 번에
python scripts/trend_follow.py --phase shadow

# 과거 소급 기록 (1회성 — events.jsonl 의 screen_done/entry 로 복원)
python scripts/shadow_ledger.py --backfill
```

데몬은 `phase_exit`(15:20)에서 **분봉 수집 직후** `update()` 를 호출한다.
순서가 중요하다 — 분봉이 먼저 저장돼야 그날 진입시각 체결가를 가상 진입가로 쓸 수 있다.

## 5. 읽는 법

```
사유                       n     손절선행     목표선행     평균R           D+5          D+20
--------------------------------------------------------------------------------
과거 미진입(소급·사유미상)         46     43%       2%   -0.33   -6.52% (n=31)  -25.51% (n=16)
실제 진입(대조군)              23     52%       4%   -0.51   +1.77% (n=17)  -18.49% (n=13)

차단된 후보 평균 -0.33R (n=46)   vs   실제 진입분 평균 -0.51R (n=23)
→ 게이트가 **손실을 막고 있다**. 현행 유지.
```

`D+N` 옆 괄호가 **그 기간을 실제로 채운 표본 수**다 — `n` 열보다 작은 게 정상(최근 기록은
아직 20영업일이 안 지났다). 이 숫자를 안 보면 소표본 평균을 전체 평균으로 착각하게 된다.

판정 기준(차단분 평균 R):

| 평균 R | 판정 | 조치 |
|--------|------|------|
| < -0.1 | 게이트가 손실을 막고 있다 | 현행 유지 |
| -0.1 ~ +0.3 | 판정 유보 | 표본 축적 |
| > +0.3 | 게이트가 수익 기회를 버리고 있다 | 임계값 완화 검토 |

**월별 분해를 반드시 같이 볼 것.** 전체 평균은 지배적 레짐에 가려진다 — 08-03 회고에서
2025 상승장이 표본을 지배해 레짐 필터 효과가 미미해 보였던 것과 같은 함정이다.

**표본 기준**: 전체 20건 미만이면 방향 참고용. **사유별 판단은 30건 이상** 쌓인 뒤에.

## 6. 초기 측정값 (2026-08-05, 소급 69건)

> 아래는 §9 결함 수정 후 재평가한 값이다.

| 구간 | 차단분 평균R | 진입분 평균R | 판정 |
|------|------------|------------|------|
| 2026-06 | -0.39 (n=9) | -0.39 (n=12) | 차단이 이득 |
| 2026-07 | **-0.37** (n=33) | **-0.70** (n=10) | 차단이 이득 |
| 2026-08 | +0.10 (n=4) | +0.02 (n=1) | 중립 |
| **전체** | **-0.33** (n=46) | **-0.51** (n=23) | 차단이 이득 |

**해석**:
- 하락장(07월)에서 게이트가 막은 종목들도 평균 -0.37R로 **역시 손실**이었다 →
  "게이트 때문에 좋은 기회를 놓쳤다"는 직관은 이 구간에선 **틀렸다**.
- 다만 진입분(-0.70R)이 차단분(-0.37R)보다 **더 나빴다**는 게 핵심 —
  차단분은 어차피 못 벌었고, 실제로 산 것들이 더 크게 잃었다.
- 08월은 표본 5건이라 판정 불가. 레짐 게이트 도입(08-03) 이후 데이터가 여기 쌓인다.

> ⚠️ 소급분은 사유가 `hist_blocked` 하나로 뭉뚱그려져 있다(어느 게이트가 막았는지 복원 불가).
> **사유별 분해는 2026-08-05 이후 데이터로만** 가능하다.

## 7. 한계

- **초기 손절/목표만 반영** — 트레일·부분익절·MA120·외인·시간청산 미반영(§2 경고 참조).
- **가상 진입가 ≠ 실제 체결가**. 슬리피지·호가 스프레드 미반영.
- **소급분의 사유 미상** — §6 참조.
- **최대 추적 20영업일**. 그 이후 큰 추세가 나와도 잡히지 않는다(`MAX_TRACK_DAYS`).
  55일(`GIVEUP_AFTER_DAYS`) 지나도 일봉을 못 찾으면 `outcome="unknown"` 으로 포기한다(상장폐지 등).
  라이브 `TREND_MAX_HOLD=60` 과 다르지만, 게이트 판정 목적엔 20일이면 방향이 잡힌다.
- **분봉 미수집일은 종가 진입 가정** — 11:00 진입 대비 편향이 생긴다(`entry_src` 로 구분 가능).
  현재 69건 중 actual 23 / minute 12 / close 34 로 **측정 시계가 섞여 있다**(분봉 수집이 08-04 시작).
- **진입 후보 선택 편향 없음**: 후보 전량을 기록하므로 사후 선택 편향은 없다.

## 8. 앞으로 이 데이터로 답할 질문

- [ ] 레짐 게이트(`TREND_REGIME_MA=60`)가 실제로 손실을 막나 — 08-03 이후 `regime` 사유 30건 축적 시 판정
- [ ] `MAX_POS=5` 가 적정한가 — `no_slot` 차단분이 지속적으로 +R 이면 슬롯 확대 근거
- [ ] `size_zero`(고가주 자본 제약) 비중 — 소액계좌가 놓치는 기회의 크기
- [ ] breadth 임계값 — `no_rebound` 로 흘러간 후보의 성과
- [ ] KOSPI 가 MA60 회복 후, 상승 레짐에서도 게이트가 이득인가 (하락장 표본만으론 불충분)

## 9. 수정 이력 — 2026-08-05 코드 리뷰 (D1~D6, **전부 수정 완료**)

도입 당일 리뷰에서 측정 정합성 결함 6건이 나왔다. 전부 고치고 `--recompute` 로 전량 재평가했다.
회귀 방지 테스트는 [tests/test_shadow_ledger.py](../tests/test_shadow_ledger.py) 21 케이스.

| # | 결함 | 수정 |
|---|------|------|
| **D1** | `taken` 대조군의 R 왜곡 — 평가 진입가는 프록시(분봉/종가)인데 손절·목표는 실체결가 기준이라 `risk = 프록시진입 − 실체결손절` 로 뒤틀림. 실측 괴리 **평균 2.49%·최대 13.28%**(06-09 SK하이닉스), 23건 중 19건이 0.5% 초과 → 손절폭 8~10% 대비 **R 왜곡 25~30%** | 레코드에 `entry_actual`(실체결가) 저장 → 있으면 최우선 사용(`entry_src="actual"`). 구 레코드는 `_migrate()` 가 `ctx.entry`/`ref_price` 에서 복원 |
| **D2** | 조기 확정이 D+N 표본에서 **패자만** 탈락 — 손절/목표 나면 즉시 `done` 이라 D+10·D+20 영구 결측. 실측 조기확정 11건이 **전부 손절** | `done` 조건을 `len(fut) >= MAX_TRACK_DAYS` 단독으로. outcome·hit_day 는 첫 도달에 고정되므로 계속 추적해도 안전. 리포트에 **D+N 별 표본 수 표기** 추가 |
| **D3** | 과거 레코드에 현행 진입시각(11:00) 적용 — 07-31 이전은 실제 09:30 | `_ENTRY_TIME_HISTORY` 이력 테이블 + 레코드 `entry_time` 스탬프. 스탬프 > 이력 > 최초값 순 |
| **D4** | 해소 불가 레코드 무한 재시도 — 상장폐지·거래정지·조회범위 초과 시 `done` 이 영영 안 붙음 | `GIVEUP_AFTER_DAYS`(55일) 경과 시 `outcome="unknown"` 으로 종료. 리포트에서 통계 제외·건수만 표기 |
| **D5** | 중복 억제가 `taken` 을 삼킴 — 오전 `size_zero` 후 장중 재시도로 실제 체결되면 대조군 표본 유실 + 차단으로 오분류 | `reason=="taken"` 이면 같은 날 기존 레코드를 **교체** |
| **D6** | `_save()` 전량 재기록 vs `record()` append 경합 — 수동 `--update` 와 데몬 15:20 동시 실행 시 유실 | `_save()` 가 저장 직전 디스크를 재읽어 **병합** |
