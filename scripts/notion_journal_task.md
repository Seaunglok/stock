# Notion 매매일지 자동 기록 작업 지시 (rule)

오늘(KST) 추세추종 결과를 Notion 세 곳에 반영한다: **A) 매매일지DB(거래행)** + **B) 종합정리 페이지(상태/보유/일지토글)** + **C) 월별 결산DB(당월 집계)**.
**중복 절대 금지. 파괴적 편집 금지**(update_content 의 search-replace 만 사용, replace_content·삭제 금지).

## ⚠️ 인증 확인 (최우선 — 0단계보다 먼저)
- 첫 Notion 도구 호출(예: 아래 A-2 조회)이 **인증 실패**(`OAuth session expired`, `Failed to authenticate`, 권한 오류 등)하면:
  **어떤 성공/반영 메시지도 출력하지 말고** `결과: ❌ Notion 인증 만료 — 재인증 필요(반영 0건)` 한 줄만 출력하고 **즉시 종료**한다.
  ※ 과거 OAuth 만료 시 에이전트가 "결과: 성공"을 허위로 출력해 실패를 은폐한 사고(2026-07 삼성생명 매도·하나금융 매수 DB 누락) 재발 방지.
  재인증 절차는 문서 하단 참조.

## 공통 0단계
- `docs/journal/<오늘 YYYY-MM-DD>-trend-journal.md` 를 Read. **파일 없으면** `결과: 오늘 일지 없음` 출력 후 **전체 종료**.
- 일지에서 다음을 파싱: 시장(KOSPI 등락%), `## 매매 (신규 N · 청산 M …)` 표, `## 보유 K종 · 평가손익 +X원` 줄과 그 아래 보유 표.

## A. 매매일지DB (거래행)
1. 신규/청산이 **0건이면 A 전체 스킵**(보유만 있는 날은 거래행 추가 안 함).
2. 데이터소스 `collection://63d8ae25-9910-4a36-ba3f-3dc942cb9733`(주식 매매일지DB)에서 **매수일자(또는 매도일자)가 오늘인 행**을 조회해 이미 기록된 종목 파악.
3. 아직 오늘자로 DB에 없는 거래만 추가(중복 금지):
   - 공통: `증권사`=키움증권, `매매이유` 앞에 🤖 추세추종.
   - **신규 매수**: `매매구분`=매수, `매수일자`=오늘, `체결단가`/`체결수량`/`총체결금액`.
   - **청산**: `매매구분`=매도, `매도일자`=오늘, `실현손익`·`수익률(%)`·`체결단가`(청산가).
4. "보유 현황" 표의 종목은 추가하지 말 것 — **그날 신규 매수·청산만** 기록.

## B. 종합정리 페이지 (`37d1459d-6f58-817a-a292-e68d432201e5`)
**먼저 fetch 로 현재 내용을 읽고**, 아래를 `update_content`(old_str→new_str 정확 일치)로 갱신한다. 일치가 불확실하면 그 항목만 건너뛴다(절대 추측 편집·전체 교체 금지).
1. **상단 callout**: `현재 상태 · YYYY-MM-DD 마감` 날짜를 오늘로, `보유 N종목 · 평가손익 +X원` 을 일지의 보유 수·평가손익으로.
2. **보유 heading**: `## 💼 현재 보유 & 손익 (YYYY-MM-DD)` 날짜를 오늘로.
3. **보유 표**(`## 📝 매매일지` 아래 표): 기존 데이터행 전체를 일지의 보유 표와 동일하게 교체(종목/수량/진입/현재/손익%/평가손익). 최고 수익 1~2종 `<tr color="green_bg">`, 최저(마이너스) 1종 `<tr color="red_bg">`. 행 수가 바뀌면 행 추가/삭제 반영.
4. **당일 토글 추가**: `## 🖥️ 운영 방법` 바로 앞에 아래 형식의 `<details>` 를 **삽입**. **단, 오늘 날짜 토글이 이미 있으면 중복 추가 금지(스킵)**:
   ```
   <details>
   <summary>YYYY-MM-DD (요일) — 한줄요약 (클릭)</summary>
   	- 시장: KOSPI ±X%. 신규 N·청산 M.
   	- 핵심: (청산 사유/하드손절/주요 손익/특이사항).
   	- 보유 K종 평가 +X원.
   </details>
   ```
   (들여쓰기는 탭. 기존 토글들과 같은 스타일 유지.)

## C. 월별 결산DB (`collection://2c0f5ffd-e5d7-4587-a765-85ba9ec084dc`)
당월 누적 집계 1행을 매 실행마다 갱신(멱등). **매매일지DB가 원천**(당일 일지 md 아님) — A 반영 후 실행.
1. 당월 = 오늘의 `YYYY년 M월`. 매매일지DB에서 **당월 거래 전체**를 SQL 로 집계:
   - `총 매수 금액` = Σ(`총체결금액` where `매매구분`=매수 AND 매수일자 당월)
   - `총 매도 금액` = Σ(`총체결금액` where `매매구분`=매도 AND 매도일자 당월)
   - `총 실현손익` = Σ(`실현손익` where 매도 AND 매도일자 당월)
2. 월별결산DB에서 `월` 제목에 `YYYY년 M월` 포함하는 행을 조회:
   - **있으면** `update_properties` 로 위 3개 숫자 갱신(제목·기존 행 유지).
   - **없으면** 새 행 생성 — `월`=`🤖 YYYY년 M월 (💰 실거래)`, 위 3개 숫자.
   ※ 6월 이전은 MOCK(모의) 시기라 제목에 `(🧪 MOCK 모의투자)` 유지 — **건드리지 말 것**.

## 마무리
- 한 줄 결과 출력 (예: `결과: DB 신규1 추가 + 종합정리 갱신(보유9·토글추가) + 7월결산 갱신` / `결과: 거래없음 — 종합정리·월결산만 갱신` / `결과: 이미 반영됨 — 스킵`).

---
## 🔑 재인증 절차 (OAuth 만료 시 — 위 인증 확인에서 실패 뜰 때)
headless `claude -p` 는 대화형 세션과 **동일 자격증명 저장소**를 쓴다. claude.ai **Notion 커넥터** OAuth 가 만료되면 무인 작업이 조용히 실패하므로, 대화형에서 재인증하면 headless 도 복구된다.
1. 터미널에서 `claude` 실행(대화형) → `/mcp` → **claude.ai Notion** 커넥터 재인증(authenticate).
   또는 claude.ai 웹 → 설정 → 커넥터에서 Notion 재연결.
2. 재인증 후 `scripts\notion_journal.cmd` 수동 1회 실행해 `결과: …` 가 정상(인증실패 아님)인지 확인.
3. 로그: `%TEMP%\notion_journal.log` — `Failed to authenticate` / `OAuth session expired` 검색으로 만료 이력 확인.
- 예약작업 `TrendJournalNotion`(평일 16:10) 의 `LastTaskResult=0` 은 **프로세스 종료코드**일 뿐 Notion 반영 성공을 보장하지 않는다 — 반드시 위 인증 확인 규칙으로 허위 성공을 차단할 것.
